Final JSON Schema Cleanup

Perform one final normalization pass across the entire academic catalog (extractor/output/academic-data.json and all section/page JSON files) to finalize the schema before database import.

1. Use a single abstraction for alternate course versions

The only abstraction for alternate versions of a course should be choices.

Any course that has multiple ways of being taken should use a choices array.

Examples include:

Regular vs Online
Regular vs Early Bird
College Prep vs Accelerated
Any future alternate versions

Remove any use of options and convert them into choices.

2. Only use choices when necessary

If a course has only one way to take it:

Remove the choices array entirely.
Store course properties directly on the course.

If a course has multiple versions:

Store shared information only once on the parent course.
Put all differing information inside each choice.
3. Parent course contains only shared information

The parent course should contain only information that is true regardless of which choice is selected.

Keep fields such as:

title
description
department
sourceReference
notes

For single-version courses also keep:

creditType
credits
gpaWaiverOption
offerings

For multi-choice courses, move those fields into each choice.

4. Each choice is self-contained

Every choice should contain the complete data needed for scheduling.

Include:

name
isOnline
creditType
credits
gpaWaiverOption
offerings
notes (only if unique to that choice)

Even if values are identical across multiple choices, keep them present for consistency.

Example:

Both Early Bird and Regular should explicitly contain

isOnline
creditType
credits
gpaWaiverOption

rather than relying on inherited values.

5. Simplify offerings

Offerings should contain only semester-specific information.

Keep:

courseCode
semesterLabel
duration
gradeLevels
prerequisites
notes (only if specific to that semester)

Remove duplicated metadata from offerings:

creditType
credits

Those belong to the course (single-version) or the choice (multi-version), not to individual semester offerings.

6. Remove empty fields

Omit optional fields when they are empty.

Examples:

remove "notes": []
remove choice notes when empty
remove offering notes when empty

Keep prerequisites as an array even when empty for consistency.

7. Preserve existing normalization

Do not change:

course codes
descriptions
credits
department assignments
grade levels
durations
prerequisite text
source references

Only restructure the JSON.

8. Validation

After completing the transformation:

validate every JSON file
ensure no data has been lost
ensure every course conforms to the finalized schema
report how many courses were modified
